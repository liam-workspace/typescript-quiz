Never lose an answer

Six rules that constrain the whole write path. Each one is a defect that already happened elsewhere.

  1. Durable before sent. The client writes every answer to IndexedDB on tap and clears it only on a per-item ack — never on request completion.
  2. Snapshot, not delta. PATCH /responses carries every answer held for one section. A delta loses answers that never made it into a batch, even when every request sent succeeds.
  3. Per-item results, never all-or-nothing. One rejected item must not roll back the rest, and item failures never fail the envelope.
  4. The server keeps what it refuses. Anything unapplied — unparseable, oversized (413), rejected — is persisted verbatim as a failed_write before the error is returned. Oversized matters most: it loses the most data while logging the least, so the capture falls back to raw bytes when no parsed body exists.
  5. Retry only what is retryable. Network and 5xx back off; 4xx other than 429 stop dead. A retried 409 is a storm, not a recovery.
  6. Flush at end of life and before submit. pagehide sends a keepalive snapshot; POST /submit carries the queue’s remainder in its own body.

Provenance: read out of _bluebik/awesome-survey, which lost answers four ways — an all-or-nothing transaction that discarded non-conflicting answers alongside one conflict; a validation pipe that rejected payloads before any handler ran, leaving no trace; delta payloads that never carried what a missed batch dropped; and a resume that overwrote unsaved local edits.

Three invariants the routes assume

Stated once here rather than repeated on every operation.

  1. Ordering is (clientInstanceId, seq), never answeredAt. A write applies when seq exceeds the stored seq for the same instance; across instances the server falls back to its own arrival order, because two devices share no clock. answeredAt is display text.
  2. Clocks are server-authoritative, and expiry is lazy. An attempt row exists from POST /attempts, but startedAt/expiresAt stay null until first section entry — reading the brief is untimed. Any request touching an expired attempt finalizes it. /result and /review then succeed with 200 — the thing the caller asked for has just become available. Everything else, including GET /attempts/{id}, refuses with 410 and carries the finalized attempt.
  3. Two things never reach a student early. On student routes choice.isCorrect appears only via /review; admin export returns it deliberately, guarded by the role claim rather than by absence. A play-capped stimulus carries no mediaUrl in the runner payload — a signed, short-lived URL is issued only by a successful /play, which is what makes “plays once” real rather than an honour system.

Attempt

The runner. POST /attempts addresses the collection; every other route here is scoped to one attempt and enforces ownership. Every write obeys the six durability rules above.

POST/api/attemptsStart, resume, or re-attempt

One call covers all three: a partial unique index constrains only status = 'in_progress', so a submitted attempt never blocks a new one. A stale in-progress attempt is finalized and the new one created in the same transaction, reported via finalizedPriorAttempt — no 410, no retry, and the news of an auto-submit is not swallowed.

PATCH/api/attempts/{id}/responsesFlush a section snapshot — the primary write path

The body is a full snapshot of every answer held for one section: never a delta, never the whole attempt. Questions in other sections are untouched, which is exactly why this is PATCH and not PUT.

Because every item shares one section, section expiry is an envelope-level 410 rather than a per-item reason — a per-item section_expired could never be true of some items and not others in the same request. A body whose questions span two sections is refused as mixed_sections for the same reason, and captured.

POST/api/attempts/{id}/submitSubmit, carrying the final answers atomically

Takes an optional final responses array so the last answers and the hand-in are one request. Without it there is a race no client can close: answer, tap Hand in, and the debounced flush is still in flight — the attempt gets graded without the answer it is still carrying. Applied first, then graded, in one transaction.

Returns identity, finality and finalFlush — one ack per item in the request, always present so the client can clear its queue from this response alone. The score is not returned; it is read from /result, so the result screen renders one shape whether reached from here, the library, or history.

Results

Both refuse an attempt that is genuinely still running. Both finalize a past-deadline attempt and then succeed — denying the caller the thing that just became available would be perverse.

GET/api/attempts/{id}/resultScore breakdown for a finished attempt

Because test_version is immutable, re-grading under unchanged rules reproduces the same totals — the stored score is a cache of a pure function over frozen content. That is what makes an admin rescore safe, and what lets a deliberate grading-rule fix apply retroactively. isPersonalBest is the exception: it is computed at read time against the student’s other attempts, so a later attempt can flip it.

Admin

Require the admin role claim. Only these five are in v1 scope — the authoring editor is a later spec, so tests reach the database through import.

GET/api/admin/failed-writesEverything the server could not apply

Without this, a rejected payload leaves no trace anywhere and a validation bug becomes silent data loss rather than a visible queue. rawBody is stored as text or bytea, never jsonb — the whole point is retaining bodies that failed to parse, which jsonb cannot hold and which would lose byte order and whitespace even when they do parse.

Schema deltas this catalog implies

Carried into step 3. Each row is a change the prototype forced that the earlier ER diagram does not yet have.

TableChangeForced by
test_section default playback columns (max_plays, allow_pause, allow_seek) plus instructions The rules screen states caps before any stimulus is loaded; stimuli may tighten but never loosen them.
attempt created_at added; started_at and expires_at become nullable The clock starts at first section entry, not at attempt creation — otherwise the last section silently loses the time spent reading the brief.
attempt_section score columns (points_earned, points_possible, correct_count, …) History renders per-section rows; trends become a GROUP BY rather than a blob walk.
response client_instance_id, client_seq Ordering must be scoped to a device. Without an instance id the guard compares unrelated clocks and the older answer can win.
failed_write new table — text or bytea body (NOT jsonb), deliberately no foreign keys Its job is holding payloads that failed validation, including ones whose attempt_id does not resolve — and ones that are not valid JSON at all, which jsonb cannot store.
stimulus_play unchanged, but now the sole gate on media access The signed URL is issued by /play, so the counter guards the bytes and not just an endpoint.
