API on this screen

Never lose an answer. Six rules, each earned from a real loss in a sibling survey app:

  1. Durable before sent. Every answer is written to IndexedDB on tap and cleared only on a per-item ack, never on request completion.
  2. Snapshot, not delta. A flush sends every answer held for the open section, so an answer missed by one batch is carried by the next.
  3. Per-item results, never all-or-nothing. One rejected answer must not roll back the others in the same request.
  4. The server keeps what it refuses. Anything unapplied — unparseable, oversized, rejected — is persisted verbatim as a failed_write before the error is returned.
  5. Retry only what is retryable. Network and 5xx back off and retry; 4xx other than 429 stop dead and surface. A retried 409 is a storm, not a recovery.
  6. Flush at end of life and before submit. pagehide sends a keepalive snapshot; submit carries the queue’s remainder in its own body.

Every request carries Authorization: Bearer <jwt>, verified against the JWKS at auth.icovn.me. The sub claim resolves to the student; no user table is owned by this service beyond its own profile row.

Correctness is withheld until finalization: choice.isCorrect never appears before an attempt is submitted or expired, and only via /review, which refuses one still in progress. Capped media is withheld until claimed: a play-limited stimulus carries no mediaUrl in the runner payload — a short-lived signed URL is issued only by a successful /play.
