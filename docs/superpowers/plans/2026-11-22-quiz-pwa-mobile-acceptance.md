# Quiz PWA — parity acceptance checklist

Reference: the prototype at https://quiz.preview.icovn.me (`docs/prototype/pwa-mobile.html`). Open it in a second Chrome window beside the app and compare screen by screen. The app wins only where the spec lists a deviation (§11). Fill the **Result** column ✅/❌ and attach screenshots to the PR. **Nothing in the matrix or the real-device section has been ticked: every row is unverified until a person runs it.** Only the automated gates at the bottom are run by tooling, and their last results are recorded in the Task 26 report.

## Setup

1. Production-like run (the service worker is disabled under `pnpm dev`, so install / offline / update rows cannot be verified there):
   ```bash
   docker compose up -d postgres
   pnpm build
   DATABASE_URL=postgresql://pp:$POSTGRES_PASSWORD@127.0.0.1:5433/pp \
   JWKS_URL=https://auth-dev.icovn.me/jwks MEDIA_SIGNING_SECRET=dev-only \
   SPA_ROOT="$PWD/packages/app/dist" PORT=3000 node packages/server/dist/main.js
   ```
   Sign in against `https://auth-dev.icovn.me` with a student account that holds the `student` role for client `quiz-web` (the issuer's dev login; redirect URI `http://localhost:3000/callback` must be registered), and seed tests with `pnpm seed`. Reminders additionally need `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT` (see the README "Practice reminders" section) in the server's environment.
2. Chrome → open `http://localhost:3000`.
3. **Phone viewport:** DevTools (⌥⌘I) → Toggle device toolbar (⇧⌘M) → dropdown "Responsive" → width **390**, height **844**, DPR 3 (pass 1); repeat everything visual at **320 × 568** (pass 2).
4. **Offline:** DevTools → Network → throttling dropdown → **Offline** (back to **No throttling** to reconnect).
5. **Service worker / install:** DevTools → Application → _Manifest_ (Installability section must list no errors), _Service workers_ (status "activated and is running"; leave "Update on reload" **off**), _Storage_ → Cache storage / IndexedDB.
6. **Reduced motion:** DevTools → ⌘⇧P → "Show Rendering" → "Emulate CSS media feature prefers-reduced-motion" = _reduce_.
7. **Overflow check** (console): `document.documentElement.scrollWidth <= innerWidth` must be `true` on every screen.
8. **Lighthouse** (DevTools → Lighthouse, Mode _Navigation_, Device _Mobile_, categories Accessibility + Best practices): both ≥ 95. Lighthouse 12+ has no PWA category — installability is the Application → Manifest check above.

## Known limits and open decisions

Copied from the implementation ledger; none blocks acceptance, two need a decision.

**Open decisions**

1. **A refused offline journal has no recovery path.** When the server refuses a journal (`offline_journal_invalid`, `offline_attempt_conflict`, a stale cached library list, a clock step over 120 s while offline, a previous sync that took over 120 s in transit) the events are kept on the device and the sync-failed alert is shown, but there is no automatic retry, no "try again" control and no export. Options: (a) an adult-triggered `retrySync(attemptId)` that clears the failed state and requests a sync (helps transient or stale-cache refusals only); (b) a journal export for support.
2. **No `GET /api/me/reminders`.** One student has one reminder subscription; turning reminders on from a second device replaces the first, and the replaced device keeps showing "on" while receiving nothing. Accepted until the server exposes the current subscription.

**Accepted limits**

- Clock: a forged skew on a hydrated attempt can gain up to (first journal event − floor) + 120 s; closing the app, setting the clock back and reopening gives the closed time free; forward wall-clock jumps under about 2 s are not counted (dead band).
- Capped audio is downloadable through the offline bundle (the URLs are the same HMAC as `/play`); play counts are audited at sync, not byte-gated.
- `apiFetch` has no per-call timeout, so a "connected but dead" network keeps choosing the remote gateway; a rare over-cap play (crash mid-apply, another tab) is refused alone at sync — the rest of the journal lands.
- A first journal post that gets no response weakens the first-send collision defence; two tabs without Web Locks can mislabel an honest journal.
- Reminders: no `pushsubscriptionchange` handler; a timeout after the push service accepted can deliver one duplicate (fixed `tag` replaces it); a 23:59 reminder can be missed; the retry throttle is per process; a failed `PUT` during VAPID key rotation leaves the old-key row on the server; an expired-session sign-out turns reminders off on that device; any 400 on `PUT` reads as "this browser cannot".
- `origin = 'offline'` is recorded but not surfaced in the admin results table.
